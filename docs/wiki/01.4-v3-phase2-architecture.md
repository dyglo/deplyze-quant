# 1.4 V3 Phase 2 Architecture

> The V3 Phase 2 architecture turns Deplyze Quant from a "live API
> proxy + AI copilot" into a **scheduled intelligence refinery**:
> external sources → BigQuery raw → cleaned → features →
> artifacts/research → gateway → UI. Every step is deterministic,
> idempotent, and lineage-tagged.

---

## 1.4.1 Wave map

V3P2 ships in lettered waves. Each wave writes to specific BigQuery
tables and exposes one or more pipeline endpoints on the quant engine:

| Wave | Subject | Writes |
|---|---|---|
| **A** | Provisioning | All 12 V3P2 tables (idempotent) |
| **B** | EDGAR ingestion | `raw_public.public_filings_raw`, `raw_documents.document_sources_raw` |
| **C** | FRED / macro ingestion | `raw_public.public_macro_raw`, `cleaned.macro_cleaned` |
| **D** | CFTC / RSS / Calendar | `raw_public.public_reports_raw`, `public_rss_raw`, `public_calendar_raw` |
| **E** | Document parsing | `raw_documents.parsed_documents_raw` |
| **F** | Entity extraction | `features.ontology_features` |
| **G** | Macro regime intelligence | `features.macro_features`, `research.macro_observations`, `artifacts.macro_artifacts` |
| **H** | Narrative intelligence | `features.narrative_features`, `research.narrative_memory`, `artifacts.narrative_artifacts`, `cleaned.narrative_cleaned` |
| **K** | Briefings generation | `research.generated_briefings` |
| **M** | Gateway exposure | (no writes — V3P2 router on the gateway) |
| **N** | Deploy + scheduler | (infra: Cloud Run manifests + Cloud Scheduler) |

## 1.4.3 BigQuery refinery (V3P2 schema)

Twelve new tables, on top of the V3P1 base, materialise V3P2. The
authoritative DDL lives in
`services/quant-engine/migrations/v3p2/001_wave_a_schemas.sql`.

### `cleaned.*`

- **`cleaned.filings_cleaned`** — normalised SEC filings, one row per
  accession. Partitioned by `observation_time` (`DAY`), clustered on
  `symbol, form_type, provider`.
- **`cleaned.narrative_cleaned`** — per-document narrative
  observations with polarity, intensity, salience, dedup hash.
  Partitioned by `observation_time`, clustered on
  `theme_id, symbol, provider`.

### `features.*`

- **`features.macro_features`** — per-series rolling features (`z_60`,
  `z_252`, `yoy`, `mom`). Partitioned by `observation_time`,
  clustered on `series_id, provider`.
- **`features.narrative_features`** — per-theme rolling stats
  (mentions, emergence, recurrence, polarity_mean, intensity_mean,
  related_symbols, window_days).
- **`features.filing_features`** — per-filing materiality / sentiment
  / event-type vector.
- **`features.ontology_features`** — entity/theme/instrument
  recognition output: `entity_id`, `entity_type`, `entity_label`,
  `salience`, `mention_count`, `co_entities`, `lineage_id`,
  `source_url`, `symbol`.

### `research.*`

- **`research.macro_observations`** — one row per regime kind per
  observation cadence (e.g. liquidity, inflation, rates, growth).
  Carries `regime_state`, `title`, `summary`, `body`, `confidence`,
  `severity`, `related_series`.
- **`research.narrative_memory`** — one row per theme, lifetime
  perspective: `emergence_at`, `last_seen_at`, `recurrence_count`,
  `lifetime_score`, `polarity_mean`, `intensity_mean`,
  `related_symbols`.
- **`research.filing_observations`** — per-filing analyst-style
  observation (insights pulled from filing parses).
- **`research.generated_briefings`** — daily / weekly / anomaly
  briefings (see §1.4.5).

### `artifacts.*`

- **`artifacts.macro_artifacts`** — regime-change artifacts (state
  flips, threshold breaches) tied back to source series.
- **`artifacts.narrative_artifacts`** — emergence / spike events for
  themes that crossed thresholds.
- **`artifacts.filing_artifacts`** — material-event artifacts from
  filings (8-K type events, 10-K/Q sentiment shifts).

Every V3P2 table carries a common envelope of fields (`provider`,
`source_url`, `source_type`, `ingestion_time`, `observation_time`,
`lineage_id`, `confidence`, `data_quality_score`, `created_at`) so
downstream consumers can trace any record back to its raw source.

Full schema details — column-by-column — live on
**[3.4 BigQuery Data Warehouse](./03.4-bigquery-data-warehouse.md)**.

## 1.4.4 Data ingestion connectors

Connectors live in `services/quant-engine/app/connectors/` and provider
adapters in `services/quant-engine/app/providers/`. Each connector is
invoked by a Cloud Scheduler-triggered endpoint and writes
lineage-tagged rows to the appropriate `raw_*` table.

| Connector | Endpoint | Source | Writes |
|---|---|---|---|
| EDGAR (filings) | `POST /v1/pipelines/ingest/edgar` | SEC EDGAR submissions API | `raw_public.public_filings_raw`, `raw_documents.document_sources_raw` |
| FRED (macro) | `POST /v1/pipelines/ingest/fred` | FRED API | `raw_public.public_macro_raw`, `cleaned.macro_cleaned` |
| COT (CFTC) | `POST /v1/pipelines/ingest/cot` | CFTC Socrata | `raw_public.public_reports_raw` |
| RSS | `POST /v1/pipelines/ingest/rss` | Configured feeds | `raw_public.public_rss_raw` |
| Calendar | `POST /v1/pipelines/ingest/calendar` | FRED `/release/dates` | `raw_public.public_calendar_raw` |

**EDGAR** requires `EDGAR_USER_AGENT` (SEC fair-use policy: must be a
real-contact User-Agent). The client backs off on 429 with tenacity
retries.

**FRED** requires `FRED_API_KEY`. We self-throttle to ~60 req/min
versus the 120/min ceiling. Defaults to ~30 institutional macro / yield
series, expanded to 17 for regime classification (see §1.4.6).

**COT** runs weekly (Fridays 18:00 ET) since CFTC publishes once a
week.

**RSS** runs every 3 hours.

**Calendar** runs at 04:00 ET daily to seed the day's release schedule.

## 1.4.5 Document parsing & entity extraction

Wave E + F together turn raw filings into structured entity / theme
features.

### Document parser — Wave E

`services/quant-engine/app/refinery/document_parser.py`. Reads from
`raw_documents.document_sources_raw`, fetches the canonical filing
text (10-K/Q, 8-K, etc.), and writes parsed text into
`raw_documents.parsed_documents_raw` with an `extraction_method`,
`extraction_quality`, and lineage back to the source URL.

Endpoint: `POST /v1/pipelines/refine/documents`. Cloud Scheduler runs
every 6 hours (`v3p2-refine-docs`).

### Entity extractor — Wave F

`services/quant-engine/app/refinery/entity_features.py`. Reads from
`raw_documents.parsed_documents_raw` + `cleaned.instruments`, applies
the ontology (`refinery/ontology.py`) to recognise:

- **Instruments** — tickers, ETFs, indices (joined against `instruments`)
- **Entities** — people, companies, organisations, places
- **Themes** — AI, geopolitics, supply chain, energy transition, etc.

Writes a row per `(entity_id, lineage_id)` to
`features.ontology_features` with `entity_type`, `entity_label`,
`salience`, `mention_count`, `co_entities`, and the original `symbol`
where applicable.

Endpoint: `POST /v1/pipelines/refine/entities`. Cloud Scheduler runs
every 6 hours, offset by 30 minutes from the parser
(`v3p2-refine-entities`).

The output is the **substrate** the narrative engine reads from (Wave H).

## 1.4.6 Intelligence generation engines

### Macro regime — Wave G

`services/quant-engine/app/intelligence/macro_regime.py` classifies
four orthogonal regime axes from `cleaned.macro_cleaned`:

- **Liquidity** — WALCL (Fed balance sheet), M2SL (M2), RRPONTSYD
  (ON RRP), DTWEXBGS (broad USD).
- **Inflation** — CPILFESL (Core CPI yoy), PCEPILFE, T10YIE
  (5y5y breakevens / market expectations).
- **Rates** — FEDFUNDS / DFF (FFR level and trend), DGS10, DGS2,
  T10Y2Y (curve).
- **Growth** — UNRATE direction, PAYEMS (NFP momentum), INDPRO yoy.

Classification is **deterministic**: each regime function reads
`SeriesSnapshot` values, applies fixed bands + z-score thresholds, and
emits a `RegimeResult` with `regime_state`, `confidence`, and
`severity`. No statistical learning, no LLM — fully reproducible per
as-of date.

The engine writes three things per run:

1. **`features.macro_features`** — z-scores, yoy/mom, and trend
   indicators for each macro series.
2. **`research.macro_observations`** — one row per regime kind, the
   "what's the regime today" observation.
3. **`artifacts.macro_artifacts`** — regime-change events
   (threshold breaches, state flips) for the timeline.

Endpoint: `POST /v1/pipelines/intelligence/macro-regime`. Scheduler:
`v3p2-macro-regime` daily at 09:45 ET.

#### Macro series required (17 total)

```
Liquidity:  WALCL · M2SL · RRPONTSYD · DTWEXBGS
Inflation:  CPIAUCSL · CPILFESL · PCEPILFE · T10YIE
Rates:      FEDFUNDS · DFF · DGS10 · DGS2 · T10Y2Y
Growth:     UNRATE · PAYEMS · INDPRO
```

(`CPIAUCSL` is included for headline-vs-core comparisons.) FRED daily
ingestion (`v3p2-ingest-fred-daily` at 09:00 ET) must complete before
the regime engine runs at 09:45 ET.

### Narrative intelligence — Wave H

`services/quant-engine/app/intelligence/narratives.py` reads
`features.ontology_features` filtered to theme entities over a
180-day lookback and tracks each theme's lifecycle:

- **Emergence score** — first appearance in the last 90 days, weighted
  by salience. Formula: `(m30 / (1 + m_prior)) * sqrt(m30) / 5.0`,
  clamped to `[0, 1]`.
- **Recurrence score** — count of prior 30-day windows in the lookback
  where the theme was present, divided by the number of windows.
- **Lifetime score** — `0.6 * recurrence + 0.3 * emergence + 0.1 *
  min(1.0, total / 100.0)`.
- **Intensity / Polarity** — aggregated salience and (where available)
  polarity from per-mention rows.

Per theme, writes to:

1. `features.narrative_features` — rolling 7d / 30d / 90d windows.
2. `research.narrative_memory` — one row per theme, lifetime
   perspective.
3. `cleaned.narrative_cleaned` — per-document narrative observations
   (one per mention).
4. `artifacts.narrative_artifacts` — emits an emergence event when
   `emergence ≥ 0.5` OR (`m7 ≥ 5` AND `recurrence < 0.5`), with
   `severity = 'high'` for `emergence ≥ 0.75`.

Endpoint: `POST /v1/pipelines/intelligence/narratives`. Scheduler:
`v3p2-narratives` daily at 10:00 ET.

## 1.4.7 Autonomous briefing generation

`services/quant-engine/app/briefings/generators.py` produces three
deterministic briefing types and writes them to
`research.generated_briefings`. **No LLM calls** — templates only.

| Briefing | Window | Inputs |
|---|---|---|
| `daily_market_intelligence` | last 24h | `macro_artifacts`, `regime_artifacts`, `narrative_artifacts`, `anomaly_artifacts`, `filing_artifacts` |
| `weekly_regime_brief` | last 7 days | `research.macro_observations` grouped by `observation_type` |
| `anomaly_summary` | last 3 days | `anomaly_artifacts`, grouped by symbol |

Each briefing has:

```
id, briefing_type, title, summary, body (markdown),
period_start, period_end,
related_symbols, tags,
model_version = "deplyze-briefings-1.0-deterministic",
provider = "deplyze_quant",
lineage_id = "briefing:<type>:<period_end>"
```

Endpoint: `POST /v1/pipelines/briefings/generate`. Scheduler:
`v3p2-briefings` daily at 10:30 ET (so it runs **after** macro
regime and narratives).

Reads back via `GET /v1/briefings/latest` on the gateway —
deduplicated to the latest row per `briefing_type` in the last 30
days. Surfaced in the **Research Library** via
`V3P2LatestBriefingsPanel`.

## 1.4.8 Lineage & reproducibility guarantees

Every V3P2 write carries:

- `provider` — the upstream source (`fred`, `sec_edgar`, `cftc`,
  `rss`, `deplyze_quant`).
- `source_url` — exact URL pulled (where applicable).
- `lineage_id` — stable string identifier per logical event, e.g.
  `narrative_obs:<theme>:<doc_lineage>`,
  `briefing:<type>:<period_end>`,
  `macro_feature:<series>:<obs_date>`.
- `observation_time` — the **event** timestamp (not the ingest
  timestamp), used for partitioning so backfills land in the correct
  partition.
- `ingestion_time` — the timestamp at which the row was written.
- `confidence` and `data_quality_score` — `[0, 1]` floats for
  downstream filtering.

This means any artifact can be replayed: the same scheduler run, on
the same as-of date, with the same source data, will produce the same
output bytes. The gateway's caching layer relies on this property —
TTLs are conservative because we know the underlying data only changes
on scheduler ticks.
